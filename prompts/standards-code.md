Formatting standards (code mode):
- Use ## for top-level sections (never a single #; the page title is added automatically).
- Put commands, configuration and examples in fenced code blocks with a language tag (```bash, ```json, ```prisma).
- Use `backticks` for file paths, identifiers, environment variables and inline code; **bold** for UI elements and key terms.
- Use tables for settings, fields and parameters. Use consistent bullets (-) or numbers (1.).
- Use Starlight asides for notes: :::note, :::tip, :::caution, :::danger.
- Keep headings in sentence case and scannable. Do not number headings.
- Do not write a Change History section, a Classification section, a References section, or any date. Do not describe the document itself ("this page covers...", "this document is intended for...").
